## 第二轮：14:12 真人样本仍失败的根因与 v2（2026-11-06 14:25）

v1 只在「后续文字」里按需回查 DB 图片消息，但 14:12 的实际请求是**引用回复图片**：

```
[14:12:12] 引用图片：候选 60 条，类型=文件/链接/卡片,图片,动画表情,文本,...，命中=None
[14:12:12] 引用回复解析：（回复 …：（一张图片，但这边没读到画面内容…））坤坤 这张图你看得见吗
[14:12:15] 回复 …：没看见 图没加载出来 你重发一次
```

DB 里图片行没有可用的 `local_id`（命中 None），而引用 XML 也不带可定位的 local_id；v1 的「后续纯文本」兜底又没覆盖引用/卡片消息，所以模型只收到失败提示。

v2 改为**图片到达时就识别并缓存，不依赖 DB 字段或引用 XML**：

- 未 @ 的群图仍不主动回复，但立即把 `msg` 本身存入 `_RECENT_IMAGE_MSG` 并在 30 秒去重后预识别，结果存入 `_RECENT_IMAGE`（10 分钟 TTL）。
- 主动识别成功的图也同时写入两个缓存。
- 引用图片先查预识别缓存，再查最近图片 `msg`，DB 60 条只作为最后兜底且不再用 `create_time` 过滤（避免字段格式不一致误杀）。
- 文字、引用、卡片消息只要含「图里 / 这张图 / 看得见吗」等都走同一个 `_image_followup()`；已有「图里是：」时不重复包裹。
- 保留 v1 的 `bridge_instance_id` 作用域修复、60 条候选、产品名「鲲鲲」。
