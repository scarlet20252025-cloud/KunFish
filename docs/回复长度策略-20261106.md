# 回复长度策略 · 2026-11-06

用户明确要求：不要靠低字数强行保持人味；认真攻略、数据分析、代码和解释该长就长、该详细就详细。

实现原则：

- 闲聊仍可自然短，语气和身份不变。
- `conversationGuidance()` 识别认真问题并注入 `【回答长度按任务决定】`，该段位于自定义人设之后、最高优先级，明确覆盖人设里「最多两句 / 不列点 / 不分段」的闲聊约束。
- `llm.buildPayload()` 看到该标记时把生成预算从默认 700 提到 4096；`finish_reason=length` 不再触发保守重试或 `cutToSentence()` 截短，保留已生成内容。
- `bot.finalize()` 对该标记直接返回原始文本，不拆气泡、不硬截断、不跑闲聊清洗，完整保留步骤、列表、代码和数据。
- 高级设置里的字数输入改称「闲聊单条参考字数」，不再是认真问题的硬上限。

局部补丁用于生产分叉基线，备份与结果见 `length-policy-result.json` / `length-policy-local-result.json`。
